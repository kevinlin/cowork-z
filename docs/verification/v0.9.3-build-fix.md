# v0.9.3 build failure and release fix

## Root cause

The [failed Build run](https://github.com/kevinlin/cowork-z/actions/runs/40532325168/job/122288191585) failed at **Audit Rust dependencies**, not compilation. Both platform test/build jobs and both pnpm audits passed. The linked run checked commit `0444e6c`; the requested v0.9.3 base `5be570851343bf8bd14593839bfa5265f6f093cc` has the same vulnerable dependency versions.

`cargo audit` reports five vulnerabilities:

| Dependency | Locked version | Advisory | Fix |
| --- | --- | --- | --- |
| rustls-webpki | 0.103.15 | [RUSTSEC-2026-0382](https://rustsec.org/advisories/RUSTSEC-2026-0382) | Update to 0.103.16 |
| webpki-root-certs | 1.0.6 | [RUSTSEC-2026-0383](https://rustsec.org/advisories/RUSTSEC-2026-0383) | Update to 1.0.10 |
| zip | 4.6.1 | [RUSTSEC-2026-0367](https://rustsec.org/advisories/RUSTSEC-2026-0367), [0368](https://rustsec.org/advisories/RUSTSEC-2026-0368), [0369](https://rustsec.org/advisories/RUSTSEC-2026-0369) | Remove unused legacy updater archive feature |

## Scope and compatibility

The fix branch starts at the exact requested commit, which was also `origin/release` when the worktree was created. The application version remains 0.9.3.

`tauri-plugin-updater` remains at 2.11.0. Its default `zip` feature enables legacy Windows ZIP and Linux tarball updater formats. Disabling defaults while explicitly retaining `rustls-tls` and `system-proxy` removes `zip` and its unused `arbitrary` dependencies. macOS tar/gzip dependencies are unconditional and remain available.

`src-tauri/tauri.conf.json` already uses `createUpdaterArtifacts: true`. [Tauri documents](https://tauri.app/plugin/updater/) this as the native v2 artifact mode, with `v1Compatible` reserved for legacy artifacts. The published v0.9.2 `latest.json` and its GitHub asset metadata were checked: all 11 platform entries resolve to native `.msi`, `.exe`, `.AppImage`, `.deb`, `.rpm`, or macOS `.app.tar.gz` artifacts. No published entry needs the removed legacy archive readers.

The Build workflow now also runs on PRs targeting `release`, allowing validation before the publish workflow is triggered by a merge.

## Local verification

- Reproduced with the same cargo-audit 0.22.2 version used in the failed job: **5 vulnerabilities, 16 allowed warnings**.
- Repeated the audit after the patch: **0 vulnerabilities, 16 unchanged allowed warnings**. No new audit exceptions.
- `cargo tree --locked --target all -e features -i tauri-plugin-updater`: only `rustls-tls` and `system-proxy` are enabled; no `zip` package remains in the lockfile.
- `cargo check --locked`: passed on macOS ARM64.
- `cargo test --locked`: passed, 102 Rust tests.
- `git diff --check`: passed.

Local compilation reused the original checkout's Cargo target cache and existing ignored sidecar binary. The release-targeted PR runs the full Linux ARM64/macOS Build workflow, including frontend and sidecar tests and builds.

## Release handoff

Merge the fix PR into `release` after its Build checks pass. Pushing to `release` triggers `publish.yml`, which builds signed artifacts and updates the draft v0.9.3 release. Signed packaging, notarization, and a live install/update are not covered by local validation or the Build workflow. Do not treat the unsigned CI checks as proof of those publish steps.
